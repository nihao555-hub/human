## 1. 产品概述

### 1.1 产品背景

短视频创作者、个人 IP、知识博主、代运营团队和 MCN 需要持续生产大量口播视频。传统流程需要反复拍摄、录音、剪辑、制作字幕和封面，生产周期长、人员成本高，且不同编辑人员的成片质量不稳定。

本产品将用户本人原视频、改写文案、克隆声音和 AI 视频处理能力整合为一条可编辑、可追踪、可批量执行的内容生产链路。用户无需重复录制目标文案，只需提供本人原视频或已有合规素材，即可让系统使用新文案和目标语音重新生成自然准确的嘴型，并完成字幕、封面和导出。

### 1.2 一句话定位

**将本人原视频自动转化为使用新文案、新语音且保持原人物、原动作和原场景的可发布短视频。**

### 1.3 第四步业务目标特别说明

数字人视频对口型不是“从一张图片重新生成一个数字人”，也不是重新设计人物动作。其目标是：

> 将本人原视频的口播替换为改写后的文案和生成语音，在保留本人形象、原有动作、背景及镜头的前提下，实现自然准确的口型同步并输出可发布视频。

原视频可以有声音，也可以没有声音。系统会删除或静音原声，并替换为第三步生成的目标语音。为了取得更好效果，画面中的人物应保持自然说话时的嘴部、表情和身体动作，不建议全程闭嘴或完全静止。

### 1.4 产品价值

1. **降本**：将脚本、配音、口型、字幕、封面和导出整合为自动化流程。
2. **提效**：一套本人视频素材可快速生产多条不同文案的视频。
3. **一致性**：统一声音、字幕、封面和导出模板，保证账号视觉风格。
4. **可控性**：每一步均可预览、编辑、重新生成和切换质量档。
5. **成本透明**：生成前显示预计费用，生成后记录实际模型和基础设施成本。
6. **可扩展性**：开源模型与闭源 API 通过统一适配层切换，避免绑定单一供应商。

## 2. 产品目标与非目标

### 2.1 MVP 目标

MVP 应完成从抖音视频或用户素材到成片导出的完整闭环：

```text
输入抖音链接或上传视频
  → 提取原文案
  → 按人设改写文案
  → 克隆音色并生成目标语音
  → 使用本人原视频生成新口型
  → 自动对齐和生成字幕
  → AI 生成封面
  → 导出成片及配套文件
```

### 2.2 MVP 成功标准

- 新用户在 10 分钟内理解并开始第一个项目。
- 合规且满足输入规范的 1 分钟任务，端到端生成成功率不低于 90%。
- 所有长耗时任务均展示阶段、进度、预计费用和失败原因。
- 任一步骤失败后可从该步骤重试，不要求用户从头开始。
- 文案、音频、口型视频、字幕和封面均可单独预览和重新生成。
- 用户在生成前可看到预计成本，生成后可查看实际成本明细。
- 导出的视频可直接满足抖音等竖屏平台的基础发布规格。

### 2.3 本期非目标

- 不从零训练基础模型。
- 不生成与原视频完全不同的身体动作或复杂新场景。
- 不提供未经授权的声音克隆、换脸或冒充他人功能。
- 不承诺自动绕过平台审核或反爬机制。
- 不在 MVP 中建设完整专业剪辑软件。
- 不在 MVP 中实现全自动发布到抖音、视频号、小红书等平台。
- 不在 MVP 中实现多人实时协作和复杂审批流。
- 不在 MVP 中实现移动端原生 App。

## 3. 目标用户与使用场景

### 3.1 目标用户

| 用户类型 | 主要痛点 | 关键诉求 |
| --- | --- | --- |
| 个人 IP / 知识博主 | 需要频繁拍摄，创作效率低 | 一次拍摄、多次复用，快速形成成片 |
| 自媒体运营人员 | 文案、配音、字幕和封面工具分散 | 一站式流程和统一素材管理 |
| 短视频代运营团队 | 多账号、多人物、多任务并行 | 人设、音色、模板和任务队列 |
| MCN / 内容工厂 | 产量大、质量不一致、成本难追踪 | 批量生产、成本统计和质量检测 |
| 企业市场团队 | 品牌内容需要统一且可审计 | 品牌模板、授权记录和历史版本 |

### 3.2 典型使用场景

#### 场景 A：对标视频改写

用户粘贴一个已获授权或公开可分析的抖音视频链接，系统提取文案，用户选择人设和改写方式，生成一条新的口播文案。

#### 场景 B：本人原视频换文案

用户上传本人已拍摄的视频，选择新文案和克隆音色，系统保留原视频动作、背景和镜头，只修改嘴型及必要面部区域。

#### 场景 C：批量账号内容生产

运营人员导入多条文案，统一选择人物视频、音色、字幕样式和封面风格，系统按任务队列生成多条视频。

#### 场景 D：高质量复杂视频兜底

开源模型处理侧脸、遮挡、快速头部动作等复杂素材失败时，用户可选择闭源高质量通道重新生成。

## 5. 核心用户流程

### 5.1 首次使用

1. 用户注册并登录。
2. 阅读并同意服务协议、隐私政策和 AI 内容使用规范。
3. 创建人物档案。
4. 上传本人视频或选择已有授权视频。
5. 上传声音样本或选择云端音色。
6. 勾选肖像权、声音权和素材使用授权声明。
7. 完成第一个视频项目。

### 5.2 单条视频完整流程

1. 新建项目。
2. 粘贴抖音链接、上传视频或直接粘贴文案。
3. 获取并确认原文案。
4. 设置人设、目标时长、语气和改写方式。
5. 选择一个改写版本。
6. 选择声音或创建克隆音色。
7. 生成目标语音并试听。
8. 上传或选择本人原视频。
9. 系统预检人物视频和音频。
10. 选择快速、高清或云端旗舰口型模式。
11. 生成无字幕口型视频。
12. 自动生成字幕时间轴并选择字幕样式。
13. 选择视频关键帧、标题和封面风格。
14. AI 生成三张封面候选。
15. 运行最终质检。
16. 导出视频、封面、字幕和文案。

### 5.3 失败恢复流程

1. 系统记录失败步骤、模型、输入、日志和已产生文件。
2. 用户查看可理解的失败原因和建议。
3. 用户可修改参数、切换模型或更换素材。
4. 仅重跑失败步骤及其后续依赖步骤。
5. 已成功步骤的产物继续复用。

## 7. 七步核心功能需求

### 7.1 第一步：提取抖音视频文案

#### 7.1.1 业务目标

从用户输入的抖音链接或上传的视频中获得可编辑的原始口播文案及时间信息，为后续改写提供输入。

#### 7.1.2 输入

- 抖音分享短链。
- 抖音视频详情页链接。
- 用户上传的 MP4/MOV 视频。
- 用户直接粘贴的文本。

#### 7.1.3 处理逻辑

```text
识别输入类型
  → 合规检查
  → 尝试读取公开文本/字幕
  → 无文本时提取音轨
  → 本地/自托管 ASR
  → 云端 ASR 兜底
  → 文本清洗和分段
```

#### 7.1.4 推荐模型

- 开源优先：FunASR Paraformer-large、WhisperX、Whisper-large-v3-turbo。
- 闭源兜底：豆包 Seed-ASR、阿里云 Paraformer、GPT-4o Transcribe。

#### 7.1.5 输出

- 原始文案。
- 句级或词级时间戳。
- 视频标题、作者、来源链接等可获得的公开元信息。
- ASR 置信度和低置信度片段。

#### 7.1.6 功能需求

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| EXT-001 | 识别常见抖音链接格式 | P0 | 有效公开链接可进入解析流程 |
| EXT-002 | 支持上传本地视频 | P0 | MP4/MOV 可成功读取并提取音轨 |
| EXT-003 | 无字幕时自动 ASR | P0 | 输出可编辑文本和时间戳 |
| EXT-004 | 标记低置信度文本 | P0 | 用户可定位并手动修正 |
| EXT-005 | 解析失败兜底 | P0 | 提示上传视频，不显示不可理解错误 |
| EXT-006 | 保留来源记录 | P0 | 项目中记录来源和用户授权确认 |

#### 7.1.7 成本

- 开源处理：约 ¥0–0.05/视频分钟。
- 闭源 ASR：约 ¥0.005–0.04/视频分钟。
- 最大长期成本不是模型调用，而是链接规则变化带来的维护工作。

### 7.2 第二步：文案改写

#### 7.2.1 业务目标

将原文案改写为符合目标账号人设、表达风格、时长和平台要求的新口播文案。

#### 7.2.2 输入

- 第一步原文案或用户输入主题。
- 账号人设。
- 目标受众。
- 目标视频时长。
- 风格、语气、结构、CTA。
- 禁用词、品牌词和合规要求。

#### 7.2.3 输出

- 1–3 个改写版本。
- 推荐标题。
- 开场钩子、正文和 CTA。
- 预计字数和口播时长。
- 风险词及修改建议。

#### 7.2.4 推荐模型

- 默认：DeepSeek、通义千问等国产大语言模型 API。
- 高质量可选：国际高端语言模型。
- 通过统一 LLM Adapter 支持切换供应商和用户自带 Key。

#### 7.2.5 功能需求

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| TXT-001 | 根据原文改写 | P0 | 保留核心事实，不逐句照抄 |
| TXT-002 | 支持人设和风格 | P0 | 输出明显符合所选人设 |
| TXT-003 | 控制目标时长 | P0 | 字数与目标时长误差不超过 20% |
| TXT-004 | 多版本生成 | P0 | 一次返回至少 2 个可比较版本 |
| TXT-005 | 手动编辑和版本保存 | P0 | 每次修改可保存为版本 |
| TXT-006 | 合规提示 | P0 | 标记广告法、医疗、金融等高风险表达 |
| TXT-007 | 成本预估 | P0 | 生成前显示预计 Token 和费用 |

#### 7.2.6 成本

- 国产 API 多版本改写：约 ¥0.02–0.30/条。
- 国际高端模型：约 ¥0.20–1.50/条。
- 实际费用取决于上下文长度、输出版本数和合规检查次数。

### 7.3 第三步：语音生成与声音克隆

#### 7.3.1 业务目标

使用用户本人或已授权音色，将最终文案生成自然、清晰、可控制语速与情绪的目标语音。

#### 7.3.2 输入

- 最终文案。
- 已保存音色或新的声音样本。
- 语速、音量、情绪、停顿和语言。

#### 7.3.3 声音样本要求

- 推荐 10–30 秒干净人声。
- 单人、无背景音乐、无明显混响。
- 支持 WAV、MP3、M4A、MP4 提取音频。
- 必须确认声音属于本人或已获得授权。

#### 7.3.4 推荐模型

- 开源自托管：CosyVoice 3。
- 开源备选：GPT-SoVITS。
- 闭源默认：MiniMax Speech。
- 闭源国际备选：ElevenLabs。

#### 7.3.5 输出

- 目标语音 WAV/MP3。
- 句段信息和时间长度。
- 使用音色、模型、参数和授权记录。

#### 7.3.6 功能需求

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| AUD-001 | 创建和管理音色 | P0 | 可上传样本、命名、试听和删除 |
| AUD-002 | 授权确认 | P0 | 未确认授权不得创建克隆音色 |
| AUD-003 | 文案生成语音 | P0 | 生成完整音频，无截断和乱码 |
| AUD-004 | 语速和停顿控制 | P0 | 参数变化在试听中可感知 |
| AUD-005 | 分段重生成 | P0 | 单句可重做并重新拼接 |
| AUD-006 | 音频质量预检 | P0 | 检测静音、削波、音量过低和异常时长 |
| AUD-007 | 原文与音频时长提示 | P0 | 显示预计时长并支持自动调整 |

#### 7.3.7 成本

- CosyVoice 3 云 GPU：约 ¥0.05–0.30/输出分钟。
- MiniMax：约 ¥0.09–0.15/约 200 字文案。
- 首次云端声音克隆约 ¥11/音色，具体以供应商账单为准。

### 7.4 第四步：本人原视频对口型

#### 7.4.1 业务目标

输入本人原视频和第三步目标语音，保留本人身份、原视频动作、背景、镜头和整体表演，只修改嘴型及必要面部区域。

#### 7.4.2 输入

- 本人原视频。
- 第三步生成的目标语音。
- 质量模式。
- 时长处理方式。

原视频有声或无声均可，原声不会作为最终音轨。原视频应尽量包含自然说话时的嘴部和表情运动。

#### 7.4.3 视频输入规范

- 单人优先。
- 推荐 1080P，最低 720P。
- 人脸清晰，嘴部不过度遮挡。
- 避免连续极端侧脸、快速出画、严重运动模糊。
- 推荐人物在需要对口型的时间段持续自然说话。
- MVP 单条建议不超过 3 分钟，长视频采用分段处理。

#### 7.4.4 时长不一致处理

| 情况 | 处理方式 |
| --- | --- |
| 目标音频短于原视频 | 裁剪原视频、保留尾部静音或调整语速 |
| 目标音频长于原视频 | 提示更换视频、适度调整语速；模板模式可循环，但完整原动作模式不可无损延长 |
| 文案差异过大 | 提示重新改写文案或选择匹配时长的视频 |

#### 7.4.5 模型策略

| 模式 | 模型 | 定位 |
| --- | --- | --- |
| 快速模式 | MuseTalk 1.5 | 成本最低、接近实时、默认通道 |
| 高清模式 | LatentSync 1.6 | 更清晰的嘴部和牙齿细节 |
| 闭源标准 | Sync Labs lipsync-2 / pro | 复杂素材的云端高质量兜底 |
| 闭源旗舰 | Sync Labs sync-3 | 侧脸、遮挡、复杂镜头和高分辨率任务 |

说明：

- MuseTalk 1.5 和 LatentSync 1.6 虽不是 2026 最新研究模型，但代码、权重和社区使用情况更成熟，适合作为工程首发。
- 2026 年研究模型可进入实验通道，但未完成许可证、社区复现和客户样片评测前，不作为默认生产模型。
- Kling LipSync 的输入模板视频最长约 10 秒，更适合短模板口播，不符合完整保留一分钟原视频动作的核心目标，因此不作为本流程主通道。

#### 7.4.6 输出

### 7.5 第五步：字幕识别与生成

#### 7.5.1 业务目标

根据已知最终文案和目标语音生成准确时间轴，输出可编辑字幕，并将字幕安全地渲染到最终视频。

#### 7.5.2 处理原则

本步骤已有最终文案和目标音频，因此优先执行“文本—音频强制对齐”，不重复依赖 ASR 猜测文案。只有文案与音频不一致时才使用 ASR 重新识别并提示用户。

#### 7.5.3 推荐模型与工具

- 中文开源：FunASR Paraformer-large。
- 多语言开源：WhisperX + Whisper-large-v3-turbo。
- 闭源中文：豆包 Seed-ASR 2.0 Enhanced。
- 闭源多语言：GPT-4o Transcribe。
- 字幕格式和烧录：SRT、ASS、FFmpeg。

#### 7.5.4 输出

- SRT 字幕。
- ASS 样式字幕。
- 已烧录字幕的视频预览。
- 字幕置信度和问题列表。

## 9. 任务队列与模型调度

### 9.1 任务状态

| 状态 | 含义 |
| --- | --- |
| queued | 等待执行 |
| preparing | 下载模型、读取素材或预处理 |
| running | 正在生成 |
| retrying | 自动重试 |
| needs_review | 需要用户处理输入问题 |
| succeeded | 成功 |
| failed | 失败 |
| canceling | 正在安全终止 |
| canceled | 已取消 |

### 9.2 调度规则

- GPU 任务按显存和模型类型限制并发。
- 语音、ASR、口型和图片任务可使用不同队列。
- 同一用户和团队支持并发上限。
- 优先级：付费旗舰 > 普通生成 > 批量低优先级任务。
- 云端 API 连续失败时自动熔断并切换备用供应商。
- 开源模型显存不足时释放模型并重新排队，不允许形成僵尸任务。

### 9.3 取消与重试

- 用户可取消排队中和运行中的任务。
- 取消后应停止计费或清楚说明已产生的不可退费用。
- 默认自动重试 1 次。
- 第二次失败后提示切换模型或修改素材。
- 所有重试必须记录原因和新增费用。

## 14. 非功能需求

### 14.1 性能

- 普通 API P95 响应时间不超过 1 秒。
- 文件上传支持断点续传和分片。
- 任务提交后 3 秒内展示排队状态。
- 任务进度最长 10 秒更新一次。
- 1 分钟 MuseTalk 快速任务目标在可用 GPU 下接近实时或数分钟内完成，最终以实测基准为准。
- 封面三张 Medium 候选目标在 2 分钟内返回，供应商排队除外。

### 14.2 稳定性

- 业务 API 月可用性目标不低于 99.5%。
- 任务状态必须持久化，Worker 重启后可恢复。
- 云端供应商失败不得导致整个平台不可用。
- 任务重复消费不得产生重复扣费或覆盖结果。
- 所有文件和数据库操作应支持幂等。

### 14.3 安全

- API Key 不得明文写入代码、日志或前端。
- 用户素材默认私有，不可通过可猜测 URL 公开访问。
- 下载链接使用短时签名 URL。
- 数据传输使用 HTTPS。
- 管理端启用强权限控制和操作审计。
- 日志不得记录完整声音样本、身份证明或密钥。

### 14.4 隐私与数据保留

- 用户可删除项目及相关素材。
- 默认原始素材保留期限应在服务协议中明确。
- 临时文件在任务结束后按策略自动清理。
- 企业客户可配置更短的数据保留周期。
- 第三方 API 是否保存输入素材必须在模型选择页明确提示。

### 14.5 可维护性

- 模型版本与业务代码解耦。
- 每次模型升级均记录版本、指标和回滚点。
- 成本单价配置化，不写死在前端。
- 错误码、用户提示和运维日志分层。
- 建立标准测试素材集和模型回归报告。

## 15. 质量检测与验收指标

### 15.1 输入质量检测

- 视频是否损坏。
- 是否检测到人脸。
- 人脸占比是否过小。
- 嘴部是否被严重遮挡。
- 是否有长时间闭嘴或静止画面。
- 音频是否静音、削波或异常。
- 视频和音频时长是否可匹配。

### 15.2 输出质量检测

| 维度 | 指标 |
| --- | --- |
| 口型同步 | Sync-C/LSE-C、Sync-D/LSE-D 或等价指标 |
| 身份保持 | CSIM 或人脸相似度 |
| 时序稳定 | FVD、闪烁检测、光流异常 |
| 画面质量 | 清晰度、黑帧、色偏、编码异常 |
| 字幕 | 时间偏差、错字、溢出和安全区 |
| 音频 | 响度、静音、削波、音画时长 |
| 封面 | 人物一致性、标题正确、画幅和清晰度 |

### 15.3 MVP 验收样本

至少准备 20 条本人样片，覆盖：

- 正脸。
- 左右侧脸。
- 胡须、牙齿和眼镜。
- 手部短暂遮挡嘴部。
- 快速头部动作。
- 明暗光线变化。
- 不同背景。
- 30 秒、1 分钟和 3 分钟时长。
- 普通话及至少一种方言或外语。

每条样片记录：

- 输入时长和分辨率。
- 目标音频语言。
- 模型和参数。
- GPU/API。
- 生成耗时。
- 峰值显存。
- 实际费用。
- 是否成功。
- 口型主观评分。
- 身份保持评分。
- 原动作保持评分。
- 背景闪烁。
- 遮挡、侧脸、胡须和牙齿问题。

## 16. 合规要求

### 16.1 必须获得的授权

- 人物肖像授权。
- 原视频使用授权。
- 声音样本和音色克隆授权。
- 文案和素材著作权授权。
- 品牌、Logo 和产品图使用授权。

### 16.2 用户确认文案

用户创建人物或音色时必须确认：

1. 人物是本人，或已获得明确授权。
2. 声音属于本人，或已获得明确授权。
3. 上传素材不侵犯第三方肖像权、声音权、隐私权和著作权。
4. 不将生成内容用于欺诈、冒充、伪造证据或其他违法行为。
5. 同意按平台和法律要求添加 AI 生成标识。

### 16.3 模型许可证

每个开源模型上线前必须分别核对：

- 代码许可证。
- 模型权重许可证。
- 基础模型许可证。
- 训练数据许可说明。
- 商用限制。
- 署名要求。
- 输出内容权利。

代码采用 MIT 或 Apache-2.0 不代表模型权重、基础模型和训练数据自动允许商业使用。

## 18. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 抖音链接规则变化 | 文案提取失败 | 支持上传视频兜底，解析器模块化维护 |
| 开源模型效果波动 | 成片质量不稳定 | 多模型通道、样片预检、闭源兜底 |
| 视频和音频时长差异过大 | 无法保留原动作 | 生成前强提示，限制差异，支持重写或调速 |
| 侧脸和遮挡 | 嘴型错误、闪烁 | 输入评分、自动切换高质量模型 |
| 云端供应商涨价或下线 | 成本和稳定性受影响 | Adapter、多供应商和价格配置 |
| GPU 长时间空闲 | 固定成本浪费 | 按需启动、批量调度、利用率监控 |
| AI 封面中文字错误 | 品牌风险 | AI 只生成视觉底图，文字程序化叠加 |
| 声音和肖像滥用 | 法律与平台风险 | 授权、审计、风控、水印和投诉处理 |
| 模型许可证不清晰 | 商业风险 | 上线前法务复核，不合规模型不得进入生产 |
| 长视频分段接缝 | 画面跳变 | 重叠窗口、关键帧对齐和人工预览 |
